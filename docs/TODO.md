## 1. 设置页 · 模型配置（P0 最后一块）

**状态**：待办 —— **等设计稿**

**为什么待办**：目前配置模型只能靠环境变量：

```bash
RAKKO_BASE_URL=... RAKKO_MODEL=... RAKKO_API_KEY=... pnpm dev
```

对开发者可接受，对普通用户不可接受。这是 P0 唯一还没做的用户可见功能。

**卡在哪**：没有设计稿。OpenDesign 稿件只有首页与对话两页。之前讨论过这页该包含什么，但没有一张可参照的图。

**开工前需要**：
1. 一张设置页设计稿（或明确说「按对话页的视觉语言自由发挥」）
2. 确认这一页是「模态对话框」还是「第三张路由」——影响导航结构

**已具备的后端能力**（本轮已做，见下）：
- provider 的增删改查、key 的加密存储
- 模型列表拉取（`GET /v1/models`）
- 连接测试
- 全部通过 IPC 暴露，UI 层只需要接

**预估**：接 UI 约 2–3 人日（后端已完成）

## 2. auto 档的真实分类器

**状态**：待办 —— P1

**为什么待办**：现在 `auto` 档与 `ask` 行为完全相同（都问）。UI 上虽然叫「自动审批」，实际没生效。

**要么做，要么改名** —— 不能让用户以为选了自动审批就少被打扰。

**需要**：写一个风险分类器：命令解析、路径判定、凭证识别。

**预估**：3–5 人日

## 3. 会话与项目的持久化

**状态**：待办

**为什么待办**：首页的「最近打开的文件」「上次会话」「我的任务」三个区块现在都是空状态，因为：
- 没有项目表
- 没有会话表
- 重启后会话全丢

**需要**：SQLite + 迁移 + IPC。

**预估**：4–5 人日

**为什么待办**：现在开发期用系统已装的 pi（方案 C）。发布时必须选：
- A：随包内置裁剪版（+90MB，离线可用）

Cindy 的做法已调研清楚（`docs/permission-design.md` 有记录），但那是配了 CDN 的方案。

**预估**：A 约 3 人日（裁剪 + 验证），B 约 3–4 人周（含发布工程）
