## 6. Markdown 不渲染（dogfood 发现，最严重）

**状态**：✅ 已修（`84df9af`）

**现象**：agent 输出的 `**加粗**`、```` ```代码块``` ````、列表全部显示成字面量。
截图见本轮 dogfood。

**原因**：`.bubble` 用 `white-space: pre-wrap` + 纯文本插入，没有 Markdown 解析。

**影响**：agent 大量使用 Markdown 组织答案，不渲染等于每次回复都是半可读的。

**修法**：引入轻量 Markdown 渲染（react-markdown 或 marked + 白名单清洗），
代码块要有等宽字体与横向滚动，链接要能点。

**注意**：必须做 XSS 防护。agent 输出可能包含用户仓库里的内容，
不能直接 `dangerouslySetInnerHTML`。

## dogfood 三项专项测试结论（2026-11-11）

用本机 agent 真实跑，不是脚本模拟。

### 测试 1：多轮工具调用改 bug —— **通过**

在仓库里埋了一个真 bug（`formatBytes` 的 `.toFixed(1)`），让 agent 修。

```
26 秒，4 次工具，3 次审批：
  bash 跑测试 → 失败
  read 读代码 → 定位第 10 行
  edit 改代码 → n.toFixed(1) → n
  bash 再跑 → 3 个全过
```

它自己完成了「复现 → 读代码 → 定位 → 修改 → 验证」的完整闭环，
最终回答还准确引用了测试输出。

### 测试 2：长命令与大量输出 —— **发现 2 个问题**

跑 `npx vitest --reporter=verbose | tail -200`：

- ✅ 执行 12 秒完成，UI 响应延迟平均 2ms、最大 2ms，**完全没卡死**
- ✅ 20KB 输出完整保存，工具卡可展开查看
- ❌ **输出带 ANSI 转义码**（`\u001b[31m` 等），界面显示成不可见字符 → **已修**
- ❌ 20KB 未截断就进 DOM，会话多了会卡 → **已修**（32KB 上限，保留头尾）

顺带发现：agent 自己诊断出「23 个测试失败是 ABI 问题不是业务逻辑」——
比我预期的准。那次失败是我切了 Electron ABI 却让它用 Node 跑测试。

### 测试 3：连续 5 个会话 —— **通过，零泄漏**

精确统计（排除工作环境里的其它 node 进程）：

| 状态 | 进程 | 内存 |
|---|---|---|
| 空应用 | 13 | 662MB |
| +1 会话 | 14 | 780MB |
| +2 会话 | 15 | 898MB |
| +3 会话 | 16 | 974MB |
| 关闭后 | 13 | 662MB |

- 每个会话约 **100–120MB**（Cindy 文档记录 150–300MB，我们更好）
- 关闭后**精确回到基线，零泄漏**
- 5 个会话全部 `SIGTERM` 正常退出，之后 `sendMessage` 都报「会话不存在」

空应用 328MB 是 Electron 基础开销（主进程+渲染+GPU+utility），不算异常。

### 这三项测试说明什么

P0 的核心链路可以承受真实使用：多轮工具、长输出、多会话并发。
剩下的问题都是体验层（Markdown 已修、ANSI 已修）与功能缺失（设置页、auto 分类器）。
